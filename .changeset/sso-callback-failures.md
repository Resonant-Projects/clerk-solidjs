`HandleSSOCallback` no longer leaves the user on the callback route when a step fails. With clerk-js 6.42.3, `setActive` rejects with a network error, and `finalize()` returns it as `error`, when it cannot confirm a new session; before, the component ignored a failed `finalize()` and left a failed activation of an existing session as an unhandled rejection. Now a failed `finalize()`, a failed activation of an existing session or a step that throws calls `navigateToSignIn` or `navigateToSignUp` for the flow of the step that failed, as a failed Protect challenge already does, so the user can try again. A failed `finalize()` keeps its error on `errors` from `useSignIn()` or `useSignUp()` and is logged in development builds; a failure `errors` does not carry is always logged with `console.error`. A `navigateToSignIn` or `navigateToSignUp` that throws is called once and logged, not retried. It also covers clerk-js signing out instead of activating a session its client does not list, even after reloading, which resolves without an error or a navigation: when `navigateToApp` was not called and the client does not list the session as signed in, the user goes back to the flow's page and the failure is logged. Each log is a fixed message naming the flow and the step that failed, plus a Clerk error code such as `network_error` when there is one; it never includes the error itself, its message, a session ID or a token. The component never navigates to the app for a session that was not activated, and once the app's navigation has started it leaves the route to the app.
